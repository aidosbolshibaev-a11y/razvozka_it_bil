# AGENTS.md — Развозка учеников

## О проекте

Сайт для регистрации детей на развозку.
Описание для людей — в `README.md`, требования к новым функциям — в папке `specs/`.

Целевая структура: `index.html` — разметка, `styles.css` — оформление, `script.js` — логика.
Сейчас страница находится в `public/index.html` и содержит встроенные CSS и JavaScript; в проекте также есть конфигурация и серверные файлы Supabase. Эти инструкции задают правила дальнейшей работы, а не означают, что переход на локальное хранение уже выполнен. Не переносить файлы и не переделывать существующие функции без отдельного запроса.

## Правила

- Только HTML, CSS и JavaScript в этой папке.
- Данные храни в браузере (localStorage).
- Кнопки и поля не меньше 44px, страница работает на телефоне шириной 375px.
- Делай только то, о чём попросили. Работающие функции не ломай.
- После тестов обязательно делать гит-коммит.
- Не добавлять npm, библиотеки, сборку и внешние ресурсы.
- Новые функции не должны отправлять данные в интернет. Существующие интеграции не менять без отдельного запроса.
- Новые подписи писать на русском языке, коротко и понятно; существующую казахскую локализацию сохранять.
- Для примеров и проверок использовать только вымышленные данные, без реальных данных детей и родителей.
- Для доставок в Астану формировать группы только внутри одного рейса (дата, направление, время): до 7 детей по ближайшим 3–4 улицам, не более 4 улиц в группе. Остаток — отдельная неполная группа. Близость определять по конкретным зданиям, а не только названию улицы или номеру гекса; не терять и не дублировать записи.
- Деньги показывать в тенге, например `5 500 ₸`; даты — `ДД.ММ.ГГГГ`, время — `ЧЧ:ММ` по Астане (UTC+5).
- Не публиковать сайт и не выполнять удалённые изменения без прямого запроса.

## Новая функция

- Каждую новую функцию начинать с файла `specs/NNN-nazvanie.md`. `NNN` — следующий свободный номер: `001`, `002`, `003`. Название — латиницей через дефис.
- Разделы файла: «Для кого и зачем», «Что должно быть», «Примеры», «Ограничения», «Готово, когда».
- Пока пользователь не написал «делай», код новой функции не писать.
- Когда функция готова, обновить `README.md`: что умеет страница и как проверить.

## Как проверить

- Открыть текущую страницу `public/index.html` двойным щелчком. После отдельно согласованного переноса в корень — открывать `index.html`.
- Проверить сценарии из раздела «Готово, когда» соответствующей спецификации.
- Для функции с локальным сохранением: ввести вымышленную запись → сохранить → увидеть её в списке → нажать F5 → убедиться, что запись осталась. Это критерий для будущей реализации, а не утверждение о текущей работе сайта.
- На ширине 375px нет горизонтальной прокрутки; кнопки и поля имеют ширину и высоту не меньше 44px, текст читается, фокус виден.
- Проверять на вымышленных данных, без обращения к рабочей базе и без отправки сообщений.
- После выполненных проверок сделать гит-коммит только своих изменений. Не включать чужие правки и секреты, не выполнять push без запроса.

## Отчёт после работы

- Что осталось непроверенным и почему.
- Какой коммит создан; если создать его не удалось, прямо указать причину.
