# Предварительная проверка адресов и выгрузка списков в Excel

## Для кого и зачем

Организатору развозки нужно перед использованием готового списка сверить адреса в Астане и видеть результат рядом с каждым адресом. Организатор должен иметь возможность выгрузить готовый список таблицей для открытия в Excel и сверки адресов.

## Что должно быть

- Предварительный просмотр готового списка для организатора с адресами поездок на машине. Записи на электричку без адреса не требуют этой проверки.
- Рядом с каждым адресом показывать текстовый статус. Начальное состояние — «Не проверено»; после ручной сверки организатор выбирает «Проверено» или «Не найдено».
- «Проверено» означает, что организатор вручную подтвердил адрес в Астане; «Не найдено» — что при сверке адрес найти не удалось. Это отметка человека, а не автоматическое подтверждение сайта.
- Дать возможность исправить отметку и вернуть «Не проверено». Статус различать текстом, а не только цветом.
- Отметки хранить в localStorage текущего браузера и восстанавливать после F5. Привязывать отметку к конкретной записи и проверенному адресу; одинаковые адреса не должны случайно менять статусы друг друга.
- Если адрес записи изменился, сбрасывать его статус на «Не проверено». Не переносить отметки на другую запись или поездку.
- При недоступном localStorage сообщать, что отметки не сохранятся, без ложного сообщения об успешном сохранении.
- Проверка не меняет исходный адрес, запись ребёнка, цену, дедлайн или существующую отправку списков. Автоматическое блокирование отправки не входит в эту функцию.
- Элементы управления не меньше 44 × 44 px; на ширине 375 px адрес, статус и действия читаются без горизонтальной прокрутки.

- Кнопка «Выгрузить для Excel» скачивает текущий готовый список таблицей, без отправки файла во внешние сервисы. Формат — настоящая книга XLSX, подтверждённая пользователем. Не выдавать CSV или HTML за XLSX сменой расширения. Формировать файл в браузере без новых библиотек.
- Колонки таблицы: №, ФИО, класс, дата поездки, направление, транспорт, время, телефон, адрес, статус проверки адреса, доверенность, цена. Колонки «Адрес» и «Статус проверки адреса» расположены рядом; одна запись занимает одну строку.
- В выгрузке сохранять текущие статусы; при отсутствии отметки у адреса указывать «Не проверено». Для записей без адреса указывать «Не требуется». Пустой список не должен скачиваться как будто он заполнен: показать «Нет записей для выгрузки».
- Текст на русском и казахском, ведущие нули телефона, кавычки, разделители и переносы строк не должны повреждать таблицу. Пользовательские значения не должны исполняться в Excel как формулы. Не выгружать PIN, хэши и секреты.
- Редактирование скачанного файла само по себе не обновляет сайт: обратный импорт не входит в текущую функцию.

## Примеры

Все адреса ниже — вымышленные тестовые строки, не сведения о реальных местах.

- «Учебная улица, дом А» → сначала «Не проверено» → организатор выбирает «Проверено» → рядом с адресом видно «Проверено» → после F5 отметка сохраняется.
- «Тестовый проезд, дом Б» → организатор выбирает «Не найдено» → рядом видно «Не найдено». Статусы других записей не меняются.
- У проверенной записи изменён адрес с «Учебная улица, дом А» на «Учебная улица, дом В» → отображается «Не проверено».
- Две записи с одинаковым адресом → отметка одной записи не меняет другую.

- В демонстрационном списке две вымышленные записи с разными статусами → нажать «Выгрузить для Excel» → открыть файл в Excel → увидеть две строки, отдельные колонки адреса и статуса и неизменённые значения.
- Список пуст → нажать выгрузку → увидеть «Нет записей для выгрузки».

## Ограничения

- Этот вариант предусматривает ручную сверку. Не подключать карты, геокодинг, API, внешние библиотеки и сетевую проверку адресов.
- Реальные адреса организатор сверяет самостоятельно вне сайта; приложение не отправляет их внешним сервисам. Для разработки и тестов использовать только вымышленные записи.
- localStorage не синхронизирует отметки между устройствами и браузерами; очистка данных браузера удаляет отметки. Не сохранять PIN и секреты вместе со статусами.
- Источник общего списка — существующая база Supabase, по прямому запросу пользователя. Нужен отдельный вход организатора с серверной проверкой роли и правом чтения общего списка. Родительский телефон + PIN не даёт таких прав; скрытая кнопка или пароль в JavaScript не являются защитой. Не открывать общий список анонимному клиенту и не помещать service role в браузер. Выдача роли производится доверенным администратором, без самостоятельного назначения роли пользователем.
- Пользователь разрешил чтение списка из Supabase для организатора в рамках этой функции. Это исключение из общего ограничения на новые сетевые обращения не разрешает отправлять адреса в карты, геокодеры или другие сервисы. Проверки — в тестовом окружении с вымышленными данными; применение миграций и настройка доступа в рабочей базе требуют отдельного поручения.
- Подтверждены XLSX и общий список из Supabase с доступом организатора. Ручные отметки на сайте с включением в выгрузку пока являются предложением; автоматическая проверка реальности адресов не согласована. Автоматическая сверка потребует пересмотра ограничения на сетевые запросы и отдельной спецификации.
- Код функции не писать до сообщения пользователя «делай». Эта спецификация не означает, что функция уже реализована.

## Готово, когда

- Реализован XLSX для общего списка Supabase и отдельный доступ организатора; место ручного проставления статусов согласовано.
- Проверено разграничение доступа: без входа и с родительскими правами общий список недоступен, организатор получает только разрешённые данные. Секреты и PIN в ответе и в файле отсутствуют.
- В согласованном просмотре у каждого адреса есть начальная отметка «Не проверено» и возможность выбрать «Проверено», «Не найдено» или сбросить отметку.
- Все примеры выше проверены на вымышленных записях, включая независимость одинаковых адресов и сброс после изменения адреса.
- После F5 в том же браузере отметки восстановлены; ошибка сохранения показана явно при недоступном хранилище.
- На ширине 375 px нет горизонтальной прокрутки, элементы управления не меньше 44 × 44 px, доступны с клавиатуры и имеют видимый фокус.
- Изменение статуса не вызывает сетевых запросов и не меняет существующие функции регистрации и отправки.
- Выгрузка проверена в Excel на вымышленных записях: строки и колонки соответствуют списку, адрес и статус рядом, кириллица и телефоны сохранены, формулы не исполняются, секретов в файле нет; обработан пустой список.
- README обновлён: описаны ручная проверка, локальное хранение, ограничения и шаги проверки.
- В отчёте указаны фактические проверки и то, что не удалось проверить; после проверок создан локальный коммит только изменений функции, без публикации.
