# Развозка Burabay IT BIL

Запись детей на развозку Щучинск ↔ Астана (только машины). Родители записываются без регистрации: телефон + PIN из 4 цифр.

## Структура
- `public/` — сайт без сборки: `index.html`, `config.js`; отдельная страница `organizer.html`, её стили и логика в `organizer.css`, `organizer.js`, генератор XLSX в `xlsx.js`
- `supabase/migrations/0001_init.sql` — таблицы, RLS, RPC-функции, проверка дедлайнов и цен на сервере
- `supabase/migrations/0002_cleanup.sql` — временное хранение: функция `cleanup_old()` и ежедневная очистка (02:00 по Астане)
- `supabase/migrations/0003_organizer_lists.sql` — закрытый реестр организаторов и RPC чтения общего списка
- `supabase/migrations/0004_delivery_location_cars.sql` — координаты выбранной точки, только машины, выдача координат родителю и организатору
- `public/location-picker.js`, `location-picker.css` — выбор метки у здания без библиотек
- `supabase/functions/send-lists/` — Edge Function: по дедлайну отправляет списки в WhatsApp
- `.github/workflows/keepalive.yml` — ежедневный пинг, чтобы бесплатный проект Supabase не засыпал

## Запуск
1. **Supabase:** создайте проект → включите расширения `pg_cron` и `pg_net` (Database → Extensions) → SQL Editor → выполните `0001_init.sql`, затем `0002_cleanup.sql`.
2. **Фронт:** в `public/config.js` впишите Project URL и anon-ключ (Project Settings → API).
3. **Хостинг:** Cloudflare Pages (или Netlify/Vercel) → подключить этот репозиторий, build command пустой, output directory `public`.
4. **WhatsApp:** задайте секреты функции и задеплойте её:
   ```
   supabase secrets set CRON_SECRET=<длинная-строка> GREEN_ID=<id> GREEN_TOKEN=<token> WA_CHAT_ID=<77001234567@c.us или id группы@g.us>
   supabase functions deploy send-lists --no-verify-jwt
   ```
5. **Расписание:** включите расширения `pg_cron` и `pg_net` (Database → Extensions), затем в SQL Editor:
   ```sql
   select cron.schedule('send-lists','*/15 * * * *',$$
     select net.http_post(
       url:='https://<project-ref>.supabase.co/functions/v1/send-lists',
       headers:='{"x-cron-secret":"<CRON_SECRET>"}'::jsonb) $$);
   ```
6. **Keepalive:** в GitHub → Settings → Secrets → Actions добавьте `SUPABASE_URL` и `SUPABASE_ANON_KEY`.

## Что менять при настройке
- Названия общих точек: `POINTS`, `PTL` в `public/index.html` **и** список `('Точка 1','Точка 2')` в `upsert_signup` (SQL).
- Цены: `PRICE` в `index.html` **и** значения 5500 / 6500 в `upsert_signup` из актуальной миграции 0004.
- Расписание рейсов: `SLOTS` в `index.html` **и** массивы времени в `upsert_signup`; дедлайны — функция `dl()` и `deadline()` в Edge Function.
- WhatsApp-провайдер: функция `sendWhatsApp` в Edge Function (сверьте формат запроса с документацией выбранного провайдера).

## Хранение данных
Данные временные: на следующий день после поездки удаляются записи, затем телефоны и PIN-хэши родителей без активных записей, а отметки об отправленных списках — через 30 дней. Ручной запуск: `select cleanup_old();`. Проверить расписание: `select * from cron.job;`.

## Организатор: проверка адресов и XLSX

Откройте `public/index.html` двойным щелчком и перейдите по ссылке «Организатору», либо откройте `public/organizer.html`. Родительский интерфейс и автоматическая отправка WhatsApp не изменены.

### Настройка доступа

Сначала настройте отдельный тестовый Supabase. После первых двух миграций примените `0003_organizer_lists.sql`. Рабочая база автоматически не обновляется.

1. В Supabase Authentication создайте и подтвердите отдельную учётную запись организатора с электронной почтой и паролем. Страница не регистрирует организаторов самостоятельно.
2. Доверенный администратор добавляет UUID этой учётной записи в закрытый реестр через SQL Editor:
   ```sql
   insert into public.organizers(user_id) values ('<UUID пользователя из Authentication>');
   ```
   Это шаблон: замените значение на UUID созданной учётной записи. Не публикуйте пароль или service role в коде. Для отзыва доступа администратор удаляет строку реестра; следующий запрос списка будет отклонён.
3. В `public/config.js` должны быть URL и только публичный ключ проекта. Вход выполняется через Supabase Auth REST, без новых библиотек.
4. Войдите на странице организатора. Выберите дату и направление, нажмите «Показать список». По умолчанию выбрана сегодняшняя дата по Астане. Показаны все записи на дату, включая ещё открытые рейсы: перед использованием обновите список.

RPC проверяет `auth.uid()` по закрытой таблице `organizers` при каждом запросе. Анонимный посетитель и родитель без членства не получают общий список; прямого доступа к таблицам у них не появляется. Схема опирается на стандартную связку [Supabase Auth](https://supabase.com/docs/guides/auth) и [SQL-функций с ограниченными правами](https://supabase.com/docs/guides/database/functions).

### Ручная проверка и выгрузка

- У адреса выберите «Проверено», «Не найдено» или «Не проверено». Проверка ручная: сайт не обращается к картам и не подтверждает существование адреса. Для записей без адреса — «Не требуется».
- В localStorage сохраняются только UUID записи, SHA-256 отпечаток адреса и рейса и статус, отдельно для проекта и организатора. Изменение адреса или рейса сбрасывает отметку при следующем обновлении списка. При недоступном хранилище виден сигнал, что отметки не сохранятся.
- Нажмите «Выгрузить для Excel». Браузер создаёт настоящий XLSX с листом «Список развозки», заголовками, фильтром и закреплённой первой строкой. Адрес и его статус стоят рядом. Телефон хранится текстом, цена — числом с форматом тенге. Значения не становятся формулами.
- Выгружается именно показанный список. При изменении фильтра старый список очищается до повторной загрузки. В пустом списке скачивания нет.
- Файл создаётся локально, без отправки внешним сервисам. PIN, хэши PIN и секреты не включаются. Обратного импорта изменений из Excel нет.
- Отметки не синхронизируются между браузерами. Очистка браузера удаляет их. Пароль и токен входа не записываются в localStorage: после F5 нужен повторный вход, затем отметки восстановятся после загрузки списка. Сеанс также заканчивается по сроку токена или кнопке «Выйти»; список очищается с экрана.
- Страница организатора на русском языке; прежняя русская и казахская локализации страницы родителей сохранены.

### Как проверить

Локальные проверки без пакетов и сетевых запросов:

```sh
node --test tests/*.test.cjs
node tests/make-xlsx-fixture.cjs /tmp/razvozka-test.xlsx
python3 tests/check-xlsx.py /tmp/razvozka-test.xlsx
```

Для полной приёмки в изолированном тестовом Supabase:

1. Создайте только вымышленные записи на одну дату: две с одинаковым учебным адресом и одну на общую точку. Войдите тестовым организатором и загрузите эту дату.
2. Отметьте первую «Проверено», вторую «Не найдено». У общей точки без адреса должно быть «Не требуется». После F5 и повторного входа отметки сохраняются; одинаковые адреса независимы.
3. Измените адрес одной записи в тестовом окружении, обновите список: её статус станет «Не проверено». Смена обратно на старый адрес не должна возвращать старую отметку.
4. Выгрузите XLSX и откройте в Excel. Сверьте строки, соседство адреса и статуса, кириллицу, переносы строк, телефон с ведущим нулём и цену. Строка, начинающаяся с `=`, должна остаться текстом.
5. Выберите дату без записей: выгрузка сообщает «Нет записей для выгрузки». Запретите localStorage: страница предупреждает, что отметки не сохранятся.
6. Проверьте отсутствие общего списка без входа, с неверным паролем и с учётной записью Supabase без членства в `organizers`. Для серверной проверки выполните `tests/organizer-access.sql` в отдельной тестовой базе после миграций; скрипт откатывает свои данные.
7. На ширине 375px проверьте отсутствие горизонтальной прокрутки, управление клавиатурой и видимый фокус. Кнопки и поля на странице организатора имеют минимум 44 × 44px.
8. Выйдите во время загрузки: поздний ответ не должен вернуть список на экран. По истечении токена вход запрашивается заново.

Проверки не должны обращаться к рабочей базе или запускать WhatsApp. Автотесты с заглушками и разбор ZIP/XML не заменяют приёмку в Excel и проверку прав в реальном тестовом Supabase.

### Если страница не открывается или не получается войти

- Откройте `public/organizer.html` в браузере (через «Открыть с помощью → Google Chrome»), а не только во вкладке редактора. В редакторе отображается исходный HTML, а локальная ссылка в чате может открыть именно редактор.
- Для входа используйте отдельную подтверждённую учётную запись организатора в Supabase Auth. Родительские телефон и PIN не подходят.
- При сообщении про `0003_organizer_lists.sql` миграция ещё не применена к выбранному проекту. При отказе в доступе администратору нужно проверить членство пользователя в `public.organizers`.
- Для работы списка требуется подключение к настроенному Supabase; открытие самого HTML не настраивает сервер и не публикует сайт.

## Известные ограничения
- PIN защищает от случайного доступа (5 неверных попыток → блок на 15 минут), но телефон + PIN — не полноценная аутентификация. Кто первым записал ребёнка на номер, тот и задал PIN этого номера.
- Персональные данные детей и родителей: проверьте требования законодательства РК к месту хранения до запуска.


## Новые требования: финальная сверка и общие точки

В `specs/003-deadline-tochki-spiski.md` описаны повторная проверка адреса здания и актуальности записей перед подтверждением/выгрузкой, исключение отмен и переносов, управление общими точками и дедлайном организатором. Итоговый список должен содержать пять основных колонок: группа, ФИО, полный адрес, телефон родителя со ссылкой WhatsApp, статус. Точный срок записи должен отображаться родителям по времени Астаны.

Это требования для дальнейшей реализации, а не описание уже работающих функций. Добавление правил в AGENTS.md не запускает автоматические проверки. Реализация начинается после команды пользователя «делай»; серверное расписание, миграции и приёмочные проверки потребуют отдельной работы. Из спецификации 002 реализована базовая карта города и переход к ручному поиску в OSM. Гексы, автоматический адресный справочник и группировка пока не внедрены.

## Фон сайта

На страницах родителей и организатора подключён локальный файл `public/assets/burabay-road.png`: сгенерированный пейзаж по мотивам Бурабая с трассой, соснами, озером и гранитными горами. Это иллюстрация, а не документальная фотография конкретной дороги. Изображение создано встроенным инструментом imagegen; полный промпт — `public/assets/burabay-road.prompt.txt`.

Формы остаются на непрозрачных карточках, над пейзажем есть светлый слой; в тёмной теме родительской страницы используется тёмный слой. Фоновая картинка загружается из проекта, без обращения к внешнему фотосервису. Если она не загрузится, останется базовый цвет фона. Для проверки откройте `public/index.html` и `public/organizer.html` в браузере и убедитесь в читаемости текста и полей.


## Карта Астаны

Откройте `public/organizer.html`: над входом есть раздел «Карта Астаны». Нажмите «Показать карту» — загрузится интерактивная карта OpenStreetMap, которую можно перемещать и масштабировать. «Обновить карту / вернуться к Астане» возвращает начальный вид. Ключ API и новые библиотеки не нужны.

Карта использует [официальный встраиваемый виджет OSM](https://wiki.openstreetmap.org/wiki/Export_tab) и загружается только по нажатию. Это общая карта города без данных пассажиров, поэтому она доступна до входа. Список организатора по-прежнему требует отдельного входа. При проблемах с картой доступны повторная загрузка и ссылка на полную карту; список и XLSX работают независимо.

Для ручной проверки введите только улицу и здание, нажмите «Подготовить поиск адреса», затем перейдите по появившейся ссылке. В OSM передаётся только введённая поисковая строка с городом Астана, не данные записей. Не вводите в это поле ФИО и телефон. Подготовка ссылки или загрузка карты не подтверждают существование здания: проверьте результат и затем вручную поставьте статус в списке.

В этом шаге нет автоматического геокодирования, подсказок существующих улиц, отображения пассажиров, гексов или расчёта групп. Эти части спецификации 002 остаются отдельной работой.

Проверки без сети: `node --test tests/map-support.test.cjs tests/organizer.test.cjs`.
В браузере проверьте открытие обеих ссылок, масштаб и перемещение карты, сбой интернета и удобство на ширине 375px. Источник и условия использования: [политика OSM](https://operations.osmfoundation.org/policies/tiles/).


## Родитель выбирает точку на карте (спецификация 004)

Электричка убрана из действующей формы, кабинета и новых отправок. Старые записи не удаляются и не превращаются в машины: родитель видит их как архивные, без изменения и отмены. Цены машин, время 14:00/16:00 и закрытие за 24 часа сохранены.

### Обязательная настройка базы

Если 0001–0003 уже применены, выполните только `supabase/migrations/0004_delivery_location_cars.sql` в отдельном тестовом проекте. Для новой базы порядок — 0001, 0002, 0003, 0004. Миграции не предназначены для повторного запуска. В файле 0003 исправлен пропущенный закрывающий разделитель тела функции; существующую успешно применённую 0003 повторять не нужно.

0004 добавляет координаты и необязательное примечание, серверную проверку области выбора и запрет новых записей другого транспорта. Клиент не задаёт цену и итоговое описание точки: их формирует сервер. Сохранение своего адреса новой формой требует этой миграции; рабочая база автоматически не менялась.

### Открытие и выбор точки

Для загрузки подложки нужен сайт через HTTP/HTTPS. Двойной щелчок по HTML по-прежнему открывает форму, но карта выбора метки предложит локальный запуск, чтобы не обращаться к OSM без корректного Referer. Без пакетов:

```sh
cd /Users/aidos/razvozka_it_bil/public
python3 -m http.server 8000 --bind 127.0.0.1
```

Откройте `http://127.0.0.1:8000/index.html`.

1. Выберите «Свой адрес» → «Открыть / обновить карту».
2. Приблизьте карту кнопкой + до конкретного здания, передвиньте её мышью/пальцем или стрелками. Нажатие на здание переносит центр к нему. Красный крест показывает будущую точку.
3. Нажмите «Подтвердить метку у здания». Кнопка доступна после загрузки видимых участков карты при масштабе 17 или ближе. Открытие карты в центре Астаны само по себе ничего не выбирает.
4. При необходимости добавьте подъезд/ориентир. После перемещения карты метку нужно подтвердить заново.
5. Создайте запись. Организатор получит те же координаты и ссылку «Открыть точку, выбранную родителем». Примечание показано отдельно. XLSX содержит координаты в описании точки.

Для общей точки подтверждение метки не требуется. Общие точки пока остаются прежними вариантами «Точка 1/Точка 2»; их настройка организатором описана в спецификации 003 и ещё не реализована.

Метка — выбранное пользователем место, не проверенный почтовый адрес. Автоматического определения названия улицы, проверки существования здания, геолокации телефона и группировки по гексам здесь нет. Сервер проверяет прямоугольную допустимую область Астаны, а не точную административную границу. Статус проверки адреса остаётся ручным и сбрасывается при изменении координат.

Тайлы OSM загружаются только для текущего видимого участка после нажатия, стандартным браузерным кэшем. Можно сменить шаблон тайлов через необязательное поле `MAP_TILES` публичной конфигурации. Не добавлять секретный ключ в публичный файл. Карте не передаются ФИО, телефоны, PIN и списки пассажиров. При сбое подложки нельзя подтвердить новую метку, а уже сохранённая серверная метка не теряется.

### Проверки

`node --test tests/*.test.cjs` проверяет выбор/сброс метки, координаты, оба языка формы, обязательность метки, общие точки, архивные записи и кабинет. Проверка разделителей SQL — только статическая; она не заменяет исполнение миграции PostgreSQL.

В отдельном тестовом Supabase после миграций выполните `tests/delivery-location.sql` и `tests/organizer-access.sql`: данные вымышленные, скрипты делают rollback. Затем вручную проверьте на ширине 375px выбор здания, сохранение и повторный вход, редактирование точки и открытие той же метки организатором. Неверные координаты и прямой запрос на электричку должны отклоняться. Не используйте рабочую базу и не запускайте отправку WhatsApp ради проверки.
