# Развозка Burabay IT BIL

Запись детей на развозку Щучинск ↔ Астана (только машины). Родители записываются без регистрации: телефон + PIN из 4 цифр.

## Структура
- `public/` — сайт без сборки: `index.html`, `config.js`; отдельная страница `organizer.html`, её стили и логика в `organizer.css`, `organizer.js`, генератор XLSX в `xlsx.js`
- `supabase/migrations/0001_init.sql` — таблицы, RLS, RPC-функции, проверка дедлайнов и цен на сервере
- `supabase/migrations/0002_cleanup.sql` — временное хранение: функция `cleanup_old()` и ежедневная очистка (02:00 по Астане)
- `supabase/migrations/0003_organizer_lists.sql` — закрытый реестр организаторов и RPC чтения общего списка
- `supabase/migrations/0004_delivery_location_cars.sql` — координаты выбранной точки, только машины, выдача координат родителю и организатору
- `public/location-picker.js`, `location-picker.css` — выбор метки у здания без библиотек
- `supabase/functions/send-lists/` — Edge Function: по дедлайну отправляет списки в WhatsApp
- `.github/workflows/keepalive.yml` — ежедневный пинг, чтобы бесплатный проект Supabase не засыпал

## Запуск
1. **Supabase:** создайте проект → включите расширения `pg_cron` и `pg_net` (Database → Extensions) → SQL Editor → выполните `0001_init.sql`, затем `0002_cleanup.sql`.
2. **Фронт:** в `public/config.js` впишите Project URL и anon-ключ (Project Settings → API).
3. **Хостинг:** Cloudflare Pages (или Netlify/Vercel) → подключить этот репозиторий, build command пустой, output directory `public`.
4. **WhatsApp:** задайте секреты функции и задеплойте её:
   ```
   supabase secrets set CRON_SECRET=<длинная-строка> GREEN_ID=<id> GREEN_TOKEN=<token> WA_CHAT_ID=<77001234567@c.us или id группы@g.us>
   supabase functions deploy send-lists --no-verify-jwt
   ```
5. **Расписание:** включите расширения `pg_cron` и `pg_net` (Database → Extensions), затем в SQL Editor:
   ```sql
   select cron.schedule('send-lists','*/15 * * * *',$$
     select net.http_post(
       url:='https://<project-ref>.supabase.co/functions/v1/send-lists',
       headers:='{"x-cron-secret":"<CRON_SECRET>"}'::jsonb) $$);
   ```
6. **Keepalive:** в GitHub → Settings → Secrets → Actions добавьте `SUPABASE_URL` и `SUPABASE_ANON_KEY`.

## Что менять при настройке
- После миграции 0005 общие точки добавляются в кабинете организатора и хранятся в `common_points`. Старые массивы в странице больше не являются источником вариантов формы.
- Цены: `PRICE` в `index.html` **и** значения 5500 / 6500 в `upsert_signup` из актуальной миграции 0004.
- После миграции 0005 время выезда добавляется в кабинете организатора и хранится в `departure_times`. Дедлайны остаются за 24 часа: `dl()` и `deadline()` в Edge Function.
- WhatsApp-провайдер: функция `sendWhatsApp` в Edge Function (сверьте формат запроса с документацией выбранного провайдера).

## Хранение данных
Данные временные: на следующий день после поездки удаляются записи, затем телефоны и PIN-хэши родителей без активных записей, а отметки об отправленных списках — через 30 дней. Ручной запуск: `select cleanup_old();`. Проверить расписание: `select * from cron.job;`.

## Организатор: проверка адресов и XLSX

Откройте `public/index.html` двойным щелчком и перейдите по ссылке «Организатору», либо откройте `public/organizer.html`. Родительский интерфейс и автоматическая отправка WhatsApp не изменены.

### Настройка доступа

Сначала настройте отдельный тестовый Supabase. После первых двух миграций примените `0003_organizer_lists.sql`. Рабочая база автоматически не обновляется.

1. В Supabase Authentication создайте и подтвердите отдельную учётную запись организатора с электронной почтой и паролем. Страница не регистрирует организаторов самостоятельно.
2. Доверенный администратор добавляет UUID этой учётной записи в закрытый реестр через SQL Editor:
   ```sql
   insert into public.organizers(user_id) values ('<UUID пользователя из Authentication>');
   ```
   Это шаблон: замените значение на UUID созданной учётной записи. Не публикуйте пароль или service role в коде. Для отзыва доступа администратор удаляет строку реестра; следующий запрос списка будет отклонён.
3. В `public/config.js` должны быть URL и только публичный ключ проекта. Вход выполняется через Supabase Auth REST, без новых библиотек.
4. Войдите на странице организатора. Выберите дату и направление, нажмите «Показать список». По умолчанию выбрана сегодняшняя дата по Астане. Показаны все записи на дату, включая ещё открытые рейсы: перед использованием обновите список.

RPC проверяет `auth.uid()` по закрытой таблице `organizers` при каждом запросе. Анонимный посетитель и родитель без членства не получают общий список; прямого доступа к таблицам у них не появляется. Схема опирается на стандартную связку [Supabase Auth](https://supabase.com/docs/guides/auth) и [SQL-функций с ограниченными правами](https://supabase.com/docs/guides/database/functions).

### Ручная проверка и выгрузка

- У адреса выберите «Проверено», «Не найдено» или «Не проверено». Проверка ручная: сайт не обращается к картам и не подтверждает существование адреса. Для записей без адреса — «Не требуется».
- В localStorage сохраняются только UUID записи, SHA-256 отпечаток адреса и рейса и статус, отдельно для проекта и организатора. Изменение адреса или рейса сбрасывает отметку при следующем обновлении списка. При недоступном хранилище виден сигнал, что отметки не сохранятся.
- Нажмите «Выгрузить для Excel». Браузер создаёт настоящий XLSX с листом «Список развозки», заголовками, фильтром и закреплённой первой строкой. Адрес и его статус стоят рядом. Телефон хранится текстом, цена — числом с форматом тенге. Значения не становятся формулами.
- Выгружается именно показанный список. При изменении фильтра старый список очищается до повторной загрузки. В пустом списке скачивания нет.
- Файл создаётся локально, без отправки внешним сервисам. PIN, хэши PIN и секреты не включаются. Обратного импорта изменений из Excel нет.
- Отметки не синхронизируются между браузерами. Очистка браузера удаляет их. Пароль и токен входа не записываются в localStorage: после F5 нужен повторный вход, затем отметки восстановятся после загрузки списка. Сеанс также заканчивается по сроку токена или кнопке «Выйти»; список очищается с экрана.
- Страница организатора на русском языке; прежняя русская и казахская локализации страницы родителей сохранены.

### Как проверить

Локальные проверки без пакетов и сетевых запросов:

```sh
node --test tests/*.test.cjs
node tests/make-xlsx-fixture.cjs /tmp/razvozka-test.xlsx
python3 tests/check-xlsx.py /tmp/razvozka-test.xlsx
```

Для полной приёмки в изолированном тестовом Supabase:

1. Создайте только вымышленные записи на одну дату: две с одинаковым учебным адресом и одну на общую точку. Войдите тестовым организатором и загрузите эту дату.
2. Отметьте первую «Проверено», вторую «Не найдено». У общей точки без адреса должно быть «Не требуется». После F5 и повторного входа отметки сохраняются; одинаковые адреса независимы.
3. Измените адрес одной записи в тестовом окружении, обновите список: её статус станет «Не проверено». Смена обратно на старый адрес не должна возвращать старую отметку.
4. Выгрузите XLSX и откройте в Excel. Сверьте строки, соседство адреса и статуса, кириллицу, переносы строк, телефон с ведущим нулём и цену. Строка, начинающаяся с `=`, должна остаться текстом.
5. Выберите дату без записей: выгрузка сообщает «Нет записей для выгрузки». Запретите localStorage: страница предупреждает, что отметки не сохранятся.
6. Проверьте отсутствие общего списка без входа, с неверным паролем и с учётной записью Supabase без членства в `organizers`. Для серверной проверки выполните `tests/organizer-access.sql` в отдельной тестовой базе после миграций; скрипт откатывает свои данные.
7. На ширине 375px проверьте отсутствие горизонтальной прокрутки, управление клавиатурой и видимый фокус. Кнопки и поля на странице организатора имеют минимум 44 × 44px.
8. Выйдите во время загрузки: поздний ответ не должен вернуть список на экран. По истечении токена вход запрашивается заново.

Проверки не должны обращаться к рабочей базе или запускать WhatsApp. Автотесты с заглушками и разбор ZIP/XML не заменяют приёмку в Excel и проверку прав в реальном тестовом Supabase.

### Если страница не открывается или не получается войти

- Откройте `public/organizer.html` в браузере (через «Открыть с помощью → Google Chrome»), а не только во вкладке редактора. В редакторе отображается исходный HTML, а локальная ссылка в чате может открыть именно редактор.
- Для входа используйте отдельную подтверждённую учётную запись организатора в Supabase Auth. Родительские телефон и PIN не подходят.
- При сообщении про `0003_organizer_lists.sql` миграция ещё не применена к выбранному проекту. При отказе в доступе администратору нужно проверить членство пользователя в `public.organizers`.
- Для работы списка требуется подключение к настроенному Supabase; открытие самого HTML не настраивает сервер и не публикует сайт.

## Известные ограничения
- PIN защищает от случайного доступа (5 неверных попыток → блок на 15 минут), но телефон + PIN — не полноценная аутентификация. Кто первым записал ребёнка на номер, тот и задал PIN этого номера.
- Персональные данные детей и родителей: проверьте требования законодательства РК к месту хранения до запуска.


## Новые требования: финальная сверка и общие точки

В `specs/003-deadline-tochki-spiski.md` описаны повторная проверка адреса здания и актуальности записей перед подтверждением/выгрузкой, исключение отмен и переносов, управление общими точками и дедлайном организатором. Итоговый список должен содержать пять основных колонок: группа, ФИО, полный адрес, телефон родителя со ссылкой WhatsApp, статус. Точный срок записи должен отображаться родителям по времени Астаны.

Это требования для дальнейшей реализации, а не описание уже работающих функций. Добавление правил в AGENTS.md не запускает автоматические проверки. Реализация начинается после команды пользователя «делай»; серверное расписание, миграции и приёмочные проверки потребуют отдельной работы. Общая карта города и поиск адреса со страницы организатора удалены по запросу пользователя. Выбранная родителем метка доступна по ссылке в записи. Гексы, автоматический адресный справочник и группировка пока не внедрены.

## Родитель выбирает точку на карте (спецификация 004)

Электричка убрана из действующей формы, кабинета и новых отправок. Старые записи не удаляются и не превращаются в машины: родитель видит их как архивные, без изменения и отмены. Цены машин, время 14:00/16:00 и закрытие за 24 часа сохранены.

### Обязательная настройка базы

Если 0001–0003 уже применены, выполните только `supabase/migrations/0004_delivery_location_cars.sql` в отдельном тестовом проекте. Для новой базы порядок — 0001, 0002, 0003, 0004. Миграции не предназначены для повторного запуска. В файле 0003 исправлен пропущенный закрывающий разделитель тела функции; существующую успешно применённую 0003 повторять не нужно.

0004 добавляет координаты и необязательное примечание, серверную проверку области выбора и запрет новых записей другого транспорта. Клиент не задаёт цену и итоговое описание точки: их формирует сервер. Сохранение своего адреса новой формой требует этой миграции; рабочая база автоматически не менялась.

### Открытие и выбор точки

Для загрузки подложки нужен сайт через HTTP/HTTPS. Двойной щелчок по HTML по-прежнему открывает форму, но карта выбора метки предложит локальный запуск, чтобы не обращаться к OSM без корректного Referer. Без пакетов:

```sh
cd /Users/aidos/razvozka_it_bil/public
python3 -m http.server 8000 --bind 127.0.0.1
```

Откройте `http://127.0.0.1:8000/index.html`.

1. Выберите «Свой адрес» → «Открыть / обновить карту».
2. Приблизьте карту кнопкой + до конкретного здания, передвиньте её мышью/пальцем или стрелками. Нажатие на здание переносит центр к нему. Красный крест показывает будущую точку.
3. Нажмите «Подтвердить метку у здания». Кнопка доступна после загрузки видимых участков карты при масштабе 17 или ближе. Открытие карты в центре Астаны само по себе ничего не выбирает.
4. При необходимости добавьте подъезд/ориентир. После перемещения карты метку нужно подтвердить заново.
5. Создайте запись. Организатор получит те же координаты и ссылку «Открыть точку, выбранную родителем». Примечание показано отдельно. XLSX содержит координаты в описании точки.

Для общей точки подтверждение метки не требуется. Общие точки пока остаются прежними вариантами «Точка 1/Точка 2»; их настройка организатором описана в спецификации 003 и ещё не реализована.

Метка — выбранное пользователем место, не проверенный почтовый адрес. Автоматического определения названия улицы, проверки существования здания, геолокации телефона и группировки по гексам здесь нет. Сервер проверяет прямоугольную допустимую область Астаны, а не точную административную границу. Статус проверки адреса остаётся ручным и сбрасывается при изменении координат.

Тайлы OSM загружаются только для текущего видимого участка после нажатия, стандартным браузерным кэшем. Можно сменить шаблон тайлов через необязательное поле `MAP_TILES` публичной конфигурации. Не добавлять секретный ключ в публичный файл. Карте не передаются ФИО, телефоны, PIN и списки пассажиров. При сбое подложки нельзя подтвердить новую метку, а уже сохранённая серверная метка не теряется.

### Проверки

`node --test tests/*.test.cjs` проверяет выбор/сброс метки, координаты, оба языка формы, обязательность метки, общие точки, архивные записи и кабинет. Проверка разделителей SQL — только статическая; она не заменяет исполнение миграции PostgreSQL.

В отдельном тестовом Supabase после миграций выполните `tests/delivery-location.sql` и `tests/organizer-access.sql`: данные вымышленные, скрипты делают rollback. Затем вручную проверьте на ширине 375px выбор здания, сохранение и повторный вход, редактирование точки и открытие той же метки организатором. Неверные координаты и прямой запрос на электричку должны отклоняться. Не используйте рабочую базу и не запускайте отправку WhatsApp ради проверки.


## Родительская страница с меню

Откройте `public/index.html` (для выбора точки карты — через локальный сервер из инструкции выше). Теперь есть три раздела:

- **Инфо** — назначение сайта, порядок записи, выбор точки у здания, поиск и изменение своих записей, дедлайн и контакт организатора Асхата. Кнопки WhatsApp и звонка добавлены по прямому запросу пользователя; сообщения автоматически не отправляются.
- **Новая запись** — существующая форма и карта. После выбора даты и времени показывается полная дата/время закрытия записи по Астане, рассчитанные по текущему правилу за 24 часа. Настраиваемый дедлайн из 003 ещё не реализован.
- **Мои записи** — поиск по прежним телефону и PIN, просмотр, изменение и подтверждаемая отмена до дедлайна.

На компьютере меню расположено слева; до 800px — компактно сверху. По умолчанию открывается «Инфо». Ссылки `index.html#info`, `index.html#form`, `index.html#mine` открывают нужный раздел; «Назад/Вперёд» переключают разделы. Переключение не пересоздаёт формы и не очищает введённые значения. После обновления страницы поиск своих записей требует повторного ввода телефона/PIN, как и прежде.

«Изменить» открывает заполненную форму. После успешного сохранения открываются «Мои записи» и виден результат операции; при ошибке форма и введённые данные сохраняются. Существующая метка не теряется при смене разделов или ширины карты.

Файлы оформления и навигации: `public/parent-layout.css`, `public/parent-navigation.js`. Существующие разделы, обработчики и серверные правила сохранены; новые миграции для этой перестройки не нужны. Требования — `specs/005-roditelskoe-menyu.md`.

Проверка: `node --test tests/*.test.cjs`. Для ручной проверки откройте страницу на ширине 375px и на компьютере, переключите разделы и язык, проверьте сохранение ввода и метки, точный дедлайн, редактирование/отмену в тестовой базе. Для проверки контакта достаточно сверить ссылки; отправлять сообщения или звонить не требуется.


## Общие точки, время выезда и города (спецификация 006)

В кабинете организатора после входа доступны добавление общей точки (город и адрес) и времени выезда (маршрут и ЧЧ:ММ по Астане). Время действует ежедневно для выбранного направления. Цена общей точки остаётся 5 500 ₸. Дубли отклоняются; изменение, отключение и удаление вариантов пока не добавлены. Адрес проверяет организатор, автоматической проверки здания нет; общая точка пока хранится без координат.

В родительской форме вместо кнопок направления — «Откуда» и «Куда»: Астана и Щучинск. При смене отправления совпадающий город назначения автоматически меняется на второй, одинаковый пункт назначения недоступен. Дополнительно города проверяются перед отправкой и SQL. Общие точки показываются только для города назначения; карта своего адреса доступна для доставки в Астану. Для Щучинска выбирается общая точка, поскольку карта ограничена Астаной.

Справочник общий для всех устройств: загружается при открытии страницы и кнопкой «Обновить точки и время». При ошибке загрузки новые записи заблокированы до успешного обновления. Организатор может повторно загрузить справочник без повторного входа. Непрерывного опроса и нового cron нет. В шапке родителя используется предоставленный `public/assets/bil.webp` вместо буквы B.

### Порядок включения

1. Сначала в отдельной тестовой базе после 0001–0004 применить **весь** `supabase/migrations/0005_trip_catalog.sql`. В нём создаются справочники и RPC, добавляется необязательная ссылка записи на общую точку, обновляется серверная проверка записи. Старые записи не переписываются. Начальные варианты «Точка 1/2» сохранены для совместимости; перед реальным использованием требуется согласовать их адреса.
2. В тестовой базе выполнить `tests/trip-catalog.sql`: вымышленные пользователи/адреса, тесты доступа, дубликатов, времени, разных городов, цены и редактирования; в конце rollback. Не запускать на рабочей базе ради проверки.
3. Проверить интерфейс с тестовой конфигурацией. После успешной проверки применить миграцию к рабочей базе **до** публикации новых файлов сайта. Новая форма требует RPC `trip_catalog`; без 0005 не разрешает запись и показывает ошибку. Старые клиенты с кодом направления и начальной общей точкой поддерживаются сервером; для новых вариантов следует обновить страницу.
4. Опубликовать файлы сайта. Автоматическое применение миграции, push и публикация в этом шаге не выполняются.

### Как проверить

`node --test tests/*.test.cjs` — без сети: города, новый справочник и время, отказ загрузки, сохранение/редактирование, управление справочником, дубликаты, завершение сеанса, прежние сценарии.

В тестовом браузере: войти организатором → добавить «Учебная улица, дом А» для Астаны и время 18:35 для Щучинск → Астана → открыть родительскую страницу, обновить варианты → выбрать их → записать вымышленного ученика → найти и изменить запись. Для обратного маршрута точка Астаны не предлагается. Проверить два языка, телефон шириной 375px, отсутствие переполнения, видимый фокус, логотип и отказ записи при сбое справочника. SQL-проверки и браузерные проверки не заменяются успешным запуском Node-тестов.


## Подсказки в разделе «Инфо»

Четыре блока о выборе адреса, просмотре/изменении записей, дедлайне и телефоне/PIN дополнены локальными SVG-иконками и миниатюрами интерфейса на HTML/CSS. Это иллюстративные примеры, а не снимки реальных записей и не интерактивные формы: они явно подписаны, содержат вымышленные данные и переводятся вместе со страницей. Поля и нужные действия выделены рамкой. Под каждым примером есть ссылка в соответствующий раздел; поиск и изменение показаны в «Моих записях», остальные поля — в «Новой записи».

Проверка: открыть «Инфо» на русском и казахском, проверить четыре примера и переходы в форму/список. Телефон в примере не используется для запросов, PIN скрыт. Указанная дата дедлайна — учебный пример, фактический дедлайн отображается в форме после выбора рейса. Проверить читаемость на телефоне шириной 375px и в тёмной теме.

## Водители и публикация (007)

Подготовлена миграция `supabase/migrations/0006_drivers_groups.sql` после 0005. Сначала применить в отдельной тестовой базе и выполнить `tests/dispatch-access.sql`; рабочая база автоматически не меняется. До применения 0006 не публиковать новые файлы сайта.

После входа организатор добавляет имя, телефон в формате 7 + 10 цифр и номер Kaspi. Загружает основной список, нажимает «Обновить водителей и записи для группировки», проверяет здания и улицы, выбирает 1–7 детей одного рейса и водителя. Группа создаётся только после дедлайна; максимум 4 разных улицы, расстояние между любыми двумя точками до 1500 м. Это ручная группировка с консервативным ограничением расстояния, не автоматическая проверка 3–4 соседних улиц и не гексы. Организатор подтверждает соседство и реальные здания; для общих точек вводит проверенные координаты. Порог 1500 м — текущий дополнительный предел, а не гарантия соседства улиц.

«Опубликовать весь рейс» разрешено, когда все активные записи распределены по актуальным группам. Родитель после повторного поиска своих записей видит только назначенного ему опубликованного водителя: имя, телефон, Kaspi для самостоятельной оплаты. Черновые назначения скрыты сервером. Изменение или отмена записи снимает публикацию всего затронутого рейса. Устаревшую группу нужно расформировать и собрать заново, затем опубликовать рейс. До этого водитель родителю не показывается. Автоматические переводы, рассылка и непрерывное обновление не добавлены.

Организатор может изменить ФИО, адрес, дату и время записи, а также отменить её, включая после дедлайна. При изменении адреса старые координаты сбрасываются; для группировки их нужно проверить заново. Направление, телефон родителя и цены в этой форме не редактируются. Родитель после дедлайна по-прежнему заблокирован и интерфейсом, и сервером. Для смены водителя расформировать группу и собрать с другим водителем. Текущий XLSX остаётся выгрузкой основного списка, назначение водителя показывается отдельным блоком кабинета.

Проверки без сети: `node --test tests/*.test.cjs`. SQL-тест проверяет запрет анонимного/обычного доступа, создание водителя, группу, публикацию и инвалидирование при отмене; содержит только вымышленные данные и rollback. Дополнительно в тестовой базе проверить границу дедлайна, разные PIN родителей, отказ публикации неполного рейса, два параллельных изменения, смену адреса, лимиты мест/улиц/расстояния. В браузере проверить полный сценарий на 375px, клавиатуру и отображение водителя в обеих локализациях. Локальные Node-тесты не заменяют эти проверки.


## Разделы кабинета и настройка дедлайна (008)

Кабинет организатора разделён на «Готовые списки», «Адреса и время» и «Водители». На компьютере меню сбоку, на телефоне сверху. Группы, редактирование записей, публикация и XLSX находятся в списках. Переключение не пересоздаёт формы; прямые ссылки #lists, #schedule, #drivers работают после входа. Выход скрывает кабинет и очищает частные списки.

Для редактирования адреса и настройки дедлайна сначала проверить и применить `0007_deadlines_addresses.sql` после 0006 в отдельной тестовой базе. Адрес меняется в справочнике для новых записей, существующие записи сохраняют прежний адрес. Настройка срока относится к конкретным дате, направлению и времени, указывается по Астане (UTC+5). Повторное открытие закрытой записи требует подтверждения; публикация затронутого рейса снимается. Без настройки действует правило 24 часов. Родителям нужно обновить варианты; перед отправкой дедлайн перечитывается, сервер проверяет актуальный срок при любых изменениях. В «Моих записях» срок приходит с сервера при поиске.

Обработчик send-lists также использует серверную dl(). Для автоматических отправок потребуется отдельное обновление Edge Function; само изменение локального файла не обновляет развёрнутую функцию. Расписание и рассылки в этом шаге не включаются.

Проверки: `node --test tests/*.test.cjs`; в тестовой базе проверить запрет изменения настроек родителю, адрес-дубль, срок позже выезда, границу срока, подтверждение повторного открытия и снятие публикации. В браузере проверить меню, сохранение заполненных форм, оба направления, фактический срок на странице родителя и 375px. Эти ручные и SQL-проверки не считаются выполненными запуском Node-тестов.


## Автосборка по гексам (009)

Сначала проверить и применить `supabase/migrations/0008_hex_groups.sql` после 0007 в отдельной тестовой базе. В «Готовых списках» заполнить дату, направление и время в блоке «Автоматически собрать по гексам», затем нажать «Собрать группы автоматически». Сервер перечитывает весь рейс, проверяет актуальный дедлайн и использует только сохранённые координаты. Создаются черновые группы до 7 детей, без назначенного водителя. Возле каждой группы выбрать водителя и нажать «Назначить водителя», затем явно опубликовать весь рейс. Автосборка не публикует и не назначает водителя сама.

Сетка локальная, без npm, H3, внешних API и передачи адресов сервисам: pointy-top axial/cube rounding, сторона 300 м, центр 51.16/71.43, метрическая проекция около Астаны. Номер гекса сохраняется для каждого участника. Алгоритм детерминированный: обход по ячейке и ID, ближайшие кандидаты из своей/шести соседних ячеек исходной точки; диаметр группы до 1500 м. Это быстрая приближённая группировка, не оптимальный маршрут и не гарантия числа улиц. Ориентир 3–4 улицы с допуском ±2 разрешён пользователем; улицы не вычисляются, дорожные препятствия и расстояния по дорогам не учитываются. Остатки образуют неполные группы. Общую карту организатора не возвращали.

Существующие группы сохраняются. Повторный запуск распределяет только ещё не сгруппированные записи, не создаёт дубликатов; устаревшую группу сначала расформировать. Записи без координат перечисляются отдельно и блокируют публикацию всего рейса до распределения. В «Адреса и время» можно задать координаты общей точки один раз: выбрать её в списке редактирования адреса и сохранить широту/долготу в отдельной форме. Старые записи без common_point_id автоматически по совпадающему тексту не связываются — их потребуется уточнить или сгруппировать вручную. Изменение координат общей точки снимает публикацию; публикация автогрупп дополнительно проверяет совпадение сохранённых и текущих координат.

Ручная сборка с проверенными улицами остаётся в раскрываемом блоке. Для неё сохраняется прежний предел четырёх улиц. Для автоматической группы ручные отметки существования улицы/здания не создаются: в служебном поле явно записано «Улица не определена (гекс)».

Проверки без сети: `node --test tests/*.test.cjs`. Интеграционный тест для отдельного Supabase: `tests/hex-groups.sql` (только вымышленные данные, rollback): права доступа, центр/границы сетки, 8 детей → 7+1, пропущенные координаты, повторный запуск, запрет публикации без водителя. Перед рабочей миграцией дополнительно проверить изоляцию рейсов, конкурентные изменения, перенастройку координат общей точки, лимит диаметра, назначение водителей и полный родительский сценарий. Проверки SQL и браузера не считаются выполненными Node-тестами. После миграции можно публиковать файлы сайта; сам коммит локальных файлов не применяет миграцию.


## Карусель подсказок Инфо (010)

Четыре карточки с иконками листаются горизонтально, автоматически раз в 6,5 секунды. Наведение и фокус внутри карусели приостанавливают автосмену. Есть стрелки и четыре переключателя; на телефоне можно пролистывать касанием. На скрытой вкладке и вне Инфо таймер останавливается. При настройке уменьшения движения автосмена изначально выключена, ручное управление доступно. Без JavaScript карточки доступны горизонтальной прокруткой. Контакт организатора расположен отдельно.

Проверка: навести курсор и дождаться остановки, убрать курсор и фокус для продолжения; проверить стрелки, клавиатуру, касание, оба языка, ширину 375px и reduced-motion. Это изменение интерфейса без миграции базы.
